# 04: 取数故障不误报，长时间故障弹窗警告

**What to build:** 让监视在网络与接口故障下仍然可信：任一市场取数失败时，控制台报错并按下一次轮询自动重试，不产生任何价格提醒（故障不会被误报成行情），另一市场照常运行；某市场连续失败满 10 分钟时，右下角弹一次故障警告（说明是数据源故障、不是行情），此后不重复，恢复成功后重新计时，再次出现长时间故障会再次警告。

**Blocked by:** 03

**Status:** done

- [x] 任一市场取数失败时控制台打印醒目的错误信息，并按轮询节奏自动重试
- [x] 取数失败的轮次不产生价格提醒，故障不会被当成行情
- [x] 一个市场故障期间，另一个市场照常取数、判定与提醒
- [x] 某市场连续失败满 10 分钟（时长可配置）时，右下角弹出一次故障警告，内容说明是数据源故障
- [x] 故障警告不重复弹出；恢复成功后计数清零，再次长时间故障会再次警告
- [x] 用模拟故障（临时改错数据地址或断网）完整走一遍上述行为

## Comments

来自票 03 实现期间的发现（2026-09-12），供本票设计「每市场独立失败计时」时参考：

- `fetch_raw(codes)` 目前一次请求取两个市场的代码（`list=gds_AU9999,hf_XAU`），网络层失败时两个市场会同时被写成同一条故障——「一个市场故障期间，另一个照常取数、判定与提醒」目前只在**解析**失败（某代码返回空或异常）时成立。若要求网络故障下两个市场也各自计时、互不牵连，需先按市场拆成两条请求（代价是每轮两次请求）。
- 取数失败的轮次目前只打印「数据源故障：…」一行，不含状态行与距阈值距离（spec 把「数据源故障」列为控制台状态三值之一），本票一并收拾。

实现记录（2026-09-12）：

- **按市场拆请求**：`fetch_raw(code)` 改为单代码，新增 `fetch_rounds(markets)` 逐市场取数并解析——网络故障下两个市场也各自计时、互不牵连（票 03 预留的取舍按「接受每轮两次请求」处理；实测两次请求对 60 秒轮询无感）。
- **新纯函数缝**：`FailureState`（连续失败起点 + 本次是否已警告）、`INITIAL_FAILURE`、`update_failures(rounds, failures, at, warn_after)`——每市场独立记账：首轮记起点、连续失败满 `FAILURE_WARN_AFTER` 产生一次 `FailureWarning` 并标记、此后不重复、成功即清零、再次长故障重新计时再警告。另有 `duration_text`（时长文案）、`failure_lines`（故障轮控制台行）、`warning_log_line`（带时间戳的告警日志行）。
- **接口重塑（票 03 审查已预告）**：新增 `MarketRound`（读数或故障，二者必居其一，构造时校验）取代 quotes/errors 两条平行映射；`evaluate_markets(rounds, states, ratio)`、`render(round_, state, failure, at, ratio, warn_after)`、`render_frame(rounds, states, failures, at, ratio, warn_after)`。
- **控制台**：故障轮输出「`!! 数据源故障：{原因}`」+「已连续失败 X（满 N 将弹出警告 / 已弹出警告）」+「状态：数据源故障」（补上票 03 指出的状态行缺口）。**失败轮不显示现价与距阈值距离**——没有读数，不用陈旧读数冒充行情（明确决定，与 US 17 同一口径）。
- **弹窗**：与价格提醒共用窗口骨架（`_show_popup` 拆出 `_fill_alert` / `_fill_failure`），琥珀色描边；内容含连续时长、起点、「最近错误」（超 72 字截断，避免撑破屏幕）与「不是行情变化；恢复后自动继续提醒」。告警同时留一行带时间戳日志（US 22「回顾什么时候被提醒过」对故障警告同样成立）。配置区新增 `FAILURE_WARN_AFTER`（timedelta，默认 10 分钟）。
- **测试**：全套 75 例通过，新增 `tests/test_failures.py` 22 例（失败记账 10、故障不误报 3、控制台 4、日志行 1、时长文案 3、MarketRound 约束 1）。`test_alerts.py` / `test_markets.py` 迁移到新接口；原「取数失败只显示错误行」用例从 `test_alerts.py` 移入 `test_failures.py` 并按新行为加严（错误行 + 时长 + 状态行 + 无现价）。
- **模拟故障端到端**（等价于「临时改错数据地址」）：只让国内代码在故障期抛错，国际始终真实请求；刷新 3 秒、警告阈值 9 秒、两市场涨破阈值设在现价下方。时间线 0–21s 国内失败、21–33s 恢复、33s 起再失败。观察：国际第 1 轮照常触发；国内故障轮零提醒；第 5 轮（连续失败 10.2s）弹一次故障警告，其后 3 轮不重复；恢复后首轮国内照常触发；再次失败重新计时，11.4s 时第二次警告。事件序列 = Alert 国际 → FailureWarning 国内 → Alert 国内 → FailureWarning 国内，与预期一致。临时脚本已删，仓库配置未改动。
- **弹窗冒烟**：真实弹窗线程同时投递价格提醒与故障警告，截图目视确认样式、由下而上叠放、不抢焦点。
- **代码审查（Standards + Spec 双轴）后的修正**：① `MarketRound` 的「二者必居其一」由注释约定改为构造时校验（审查指出：坏轮次会被 `update_failures` 当成成功、清零失败计数）；② `evaluate_markets` 与 `update_failures`/`render` 统一用 `round_.failed` 同一谓词；③ `_short` 去掉无人覆盖的参数；④ 队列与泵更名 `_events`/`_pump_events`（已不只装价格提醒）；⑤ `API_URL` 占位符随单码请求改名 `{code}`；⑥ `CONTEXT.md` 补录「数据源故障」「故障警告」两个术语。
- **审查中判读后不采纳**：测试 fixture 三份逐字拷贝（沿用票 03 的决定——各测试文件自洽、各验各的行为，代价是 `console_text` 小助手重复）；`at`/`rearm_ratio`/`warn_after` 打包成上下文类型（`rearm_ratio` 在判定核心各处都是平铺参数，只给渲染单独造类型反而不一致，如日后参数继续增多再议）；故障弹窗的「起点/最近错误」与控制台的时长行（判为对「说明是数据源故障」和「醒目」有实质帮助，保留）。
- **留给人工的验收项**：故障警告的提示音听感（与价格提醒同一代码路径，响度需人耳确认）。

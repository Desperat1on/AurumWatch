# 01: 骨架贯通——双击运行，国内、国际金价实时上屏

**What to build:** 双击「启动金价监视.bat」即开始监视：控制台上下两段分别显示国内金价（沪金99，元/克）与国际金价（伦敦金，美元/盎司）的现价和行情数据时间，每 60 秒自动刷新，关闭窗口即停止。本票把整个功能的骨架一次贯通：专用 Conda 环境、两个数据源的取数（含 GBK 解码与 Referer 头）、中文名启动器、出错不闪退。不含阈值与任何提醒。

**Blocked by:** 无（可立即开工）

**Status:** done

- [x] 专用 Conda 环境 `aurum`（Python 3.13）创建完成，第三方依赖仅 `requests`
- [x] 双击「启动金价监视.bat」即可运行，不需要命令行、不需要手动激活环境
- [x] 控制台分两段显示国内金价与国际金价，各含现价和数据时间
- [x] 每 60 秒自动刷新；间隔可在主脚本顶部配置区修改
- [x] 显示数值与行情网站一致（2026-09-12 实测参考：国内约 940 元/克，国际约 4348 美元/盎司）
- [x] 脚本异常退出时窗口停住并显示错误，双击场景不闪退
- [x] 关闭窗口即停止监视（Ctrl+C 同样有效）

## Comments

实现记录（2026-09-12）：

- **换算系数修正**：spec 称「国内接口返回分/克、乘 0.01」，实测 `gds_AU9999` 字段值 940.00 直接等于参考价「约 940 元/克」，应为元/克、乘 1。若照 spec 乘 0.01 将显示 9.40，差 100 倍。两个市场均已用 `Decimal` 承载价格，避免浮点噪声。见 `watch_gold.py` 配置区 `scale` 注释。
- **hf_XAU 时间字段带毫秒**（如 `04:54:00.123`），解析时截断到秒。
- 新增 `tests/test_watch_gold.py`（标准库 unittest，13 个用例）覆盖解析器与刷新对齐：两个市场的价格与数据时间、毫秒截断、换算系数、空数据/缺变量/错代码/非数字价格报错、整分对齐。解析器为纯函数（一行响应文本 + 代码进，Quote 出）。spec 的「唯一测试对象」指的是触发判定核心（02 起交付）；解析器是另一个真实逻辑缝，按 TDD 一并覆盖。
- 刷新改为与系统时钟整分钟对齐（`next_refresh_delay`），避免与行情源的采样时刻错位导致跨轮次数据未变化——这是 02 起「穿越触发」会依赖的性质。
- **.bat 行尾坑**：LF 行尾的 `.bat` 在 `autocrlf=false` 的检出上会被 cmd.exe 错位解析（实测跳过 `chcp`/`cd` 并报 'not recognized'）。已用 `.gitattributes` 的 `*.bat -text` 固定仓库内 CRLF 字节。
- 手动验收：取数实测显示 `940.00 元/克`、`4348.35 美元/盎司`，与行情源一致（另用上金所接口交叉核对量级）；正常路径、错误路径（含 traceback + 回车停住 + 退出码 1）、Ctrl+C 中断（模拟信号实测打印「监视已停止。」）均通过。
- 挂机形态：前台控制台窗口，Ctrl+C 打印「已停止」后退出；关闭窗口即停止。

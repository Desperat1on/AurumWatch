# Spec: 金价监视与阈值弹窗提醒

Status: done
日期: 2026-09-12

## Problem Statement

我关心金价（国内人民币克价和国际美元盎司价），希望在价格涨到或跌到某个位置时第一时间知道。但我不可能一直手动刷新行情网页：白天要工作，而行情在下午和夜里（夜盘、伦敦时段）都在走。手动刷新既容易错过时刻，也谈不上"盯着"。

## Solution

一个双击就能运行的监视脚本：开跑后持续轮询国内金价与国际金价，在控制台里实时显示当前价格；价格涨破或跌破我预先在脚本里设定的阈值时，屏幕右下角弹出一个不打断工作的小窗、附一声提示音。提醒后脚本继续监视，价格明显回落再突破时会再次提醒；断网等故障不会误报，故障持续过久会另行警告。

## User Stories

1. 作为用户，我希望双击一个启动文件就开始监视，以便不用记命令行、不用开终端。
2. 作为用户，我希望同一个脚本同时监视国内金价（沪金99，元/克）与国际金价（伦敦金，美元/盎司），以便不用在两个网页之间来回切换。
3. 作为用户，我希望国内、国际各自的阈值都在脚本顶部的配置区设置，以便改数值时不需要读懂整段代码。
4. 作为用户，我希望每个市场分别设「涨破」和「跌破」两个阈值，以便涨、跌两个方向都能被提醒。
5. 作为用户，我希望某个方向的阈值留空或填 0 时该方向不启用，以便只关心单边行情时不受多余打扰。
6. 作为用户，我希望控制台持续显示两个市场的现价、数据时间、距各阈值的距离，以便随时确认脚本活着、还差多少。
7. 作为用户，我希望每 60 秒自动刷新一次，且间隔可在脚本顶部修改，以便兼顾及时性和轻量。
8. 作为用户，我希望价格涨破阈值时看到右下角弹窗和提示音，以便第一时间知道。
9. 作为用户，我希望价格跌破阈值时同样被提醒，以便下跌行情也不错过。
10. 作为用户，我希望弹窗显示方向、市场、现价、阈值和数据时间，以便一眼判断发生了什么、数据新不新。
11. 作为用户，我希望弹窗出现在屏幕右下角、不抢焦点、30 秒后自动消失也可以点击关闭，以便不打断手头的工作。
12. 作为用户，我希望提示音可以关闭，以便在安静场合使用。
13. 作为用户，我希望触发后脚本继续运行、不必手动重启，以便设置一次就长期挂着。
14. 作为用户，我希望价格明显回落（默认回落阈值 0.1%）后再次突破时才再次提醒，以便价格贴着阈值抖动时不被反复打扰。
15. 作为用户，我希望这个回落缓冲比例可在脚本顶部修改，以便按自己的行情观感调整。
16. 作为用户，我希望脚本启动时如果价格已经越线就立即提醒，以便知道"我等的条件其实早已满足"。
17. 作为用户，我希望休市时段从控制台显示的数据时间看出数据没在更新，以便不把静止数据当成实时行情。
18. 作为用户，我希望断网或接口异常时脚本静默重试、不产生价格提醒，以便故障不会被误当成行情。
19. 作为用户，我希望长时间（默认 10 分钟）取数失败时收到一次弹窗警告，以便知道监视实际上失效了。
20. 作为用户，我希望故障恢复后再次出现长时间故障会再次警告，以便每次失效都不会被静默吞掉。
21. 作为用户，我希望国内、国际两个市场互不影响，一个取数失败时另一个照常监视。
22. 作为用户，我希望每次触发都在控制台留一行带时间戳的日志，以便回顾什么时候被提醒过。
23. 作为用户，我希望脚本运行在我专用的 Conda 环境里，以便不弄坏电脑上其他 Python 项目。
24. 作为用户，我希望脚本出错退出时窗口停住并显示错误，以便双击运行时也能看到出了什么问题。
25. 作为用户，我希望启动文件是中文名，以便在文件夹里一眼认出来。

## Implementation Decisions

- 交付物为两个根目录文件：主脚本（`watch_gold.py`）与双击启动器（`启动金价监视.bat`）。全部可配置项集中在主脚本顶部「配置区」：四个阈值、轮询间隔、重新武装带比例、弹窗停留时长、提示音开关、故障警告时长。
- 数据源：新浪财经行情接口（结构化行情，非 HTML 抓取）。国内用 `gds_AU9999`（沪金99 = 上金所 Au99.99），国际用 `hf_XAU`（伦敦金 XAU/USD）。请求需带 Referer 头，响应按 GBK 解码，与 2026-09-12 在本机实测一致。HTML 抓取被否决：网页改版即失灵。
- 轮询：单线程循环，每次取数成功后立即判定两个市场；不做交易时段、节假日判断。
- 触发模型：每个（市场 × 方向）持有独立状态：潜伏（armed）/ 已触发（fired）。判定与状态迁移实现为纯函数：输入「一次读数（价格 + 数据时间）+ 配置 + 当前状态」，输出「提醒事件 + 新状态」。规则：涨破 = 最新价 ≥ 阈值；跌破 = 最新价 ≤ 阈值；触发后进入 fired，只有当价格回到阈值另一侧并越过重新武装带（阈值 × 0.1%）才回到 armed。启动后首次读数即参与判定。取数失败的轮次不进入该函数。
- 核心与副作用分离：判定核心不感知网络、控制台与弹窗；取数、打印、弹窗分别是最外层的副作用。这是本设计唯一的测试缝。
- 弹窗：tkinter 自绘无边框置顶小窗，锚定屏幕右下角；显示期间不阻塞轮询（防刷屏由穿越触发保证，而非阻塞）；30 秒自动消失、点击提前关闭；触发时 winsound 短提示音（可关）。不发送系统原生通知（避免被专注助手/勿扰模式拦截）。
- 控制台：上下两段分别输出国内/国际的现价、数据时间、距各阈值距离、当前状态（监视中 / 已触发待回落 / 数据源故障）。
- 失败处理：每个市场独立记录连续失败时长；失败轮只在控制台打印错误并按下一次轮询自动重试；连续失败达到 10 分钟弹一次故障警告（同样式弹窗，说明是数据源故障），告警后不重复，恢复成功后计数清零，再次出现长故障会再次警告。
- 运行环境：专用 Conda 环境 `aurum`（Python 3.13，位于 `D:\App\Anaconda\anaconda3\envs\aurum`），第三方依赖仅 `requests`；其余（tkinter、winsound、时间与解析）均为标准库。
- 启动器：`.bat` 用环境内 `python.exe` 的绝对路径调用主脚本（不依赖 conda 激活），脚本退出后 `pause`，保证双击场景能看到报错。

## Testing Decisions

- 好的测试只验证外部行为：喂入一串价格读数与配置，断言产生的提醒事件序列（何时弹、弹哪个方向、哪些轮次不该弹）；不断言内部函数名、对象结构等实现细节。
- 唯一测试对象：触发判定核心（上述纯函数）。覆盖场景：涨破/跌破基本触发；未达阈值不触发；触发后价格停留或贴着阈值抖动不重复触发（重新武装带）；回落越过缓冲带后再次触发；启动即越线立即触发；留空/0 阈值的市场不参与；同一市场两方向互不干扰；国内、国际互不串扰。
- 测试框架：Python 标准库 `unittest`（`python -m unittest`），不引入新依赖。这是仓库的第一个测试，无既有先例可循。测试只依赖纯函数，不碰网络与 UI。
- 不写自动化测试的部分（手动验收代替）：网络取数（跑真实脚本看控制台数据）、弹窗外观与位置（目视）、提示音、`.bat` 双击启动与 pause 行为。
- 手动验收：把阈值临时设到现价附近，亲眼看到一次弹窗触发，再改回。

## Out of Scope

- 交易时段、节假日判断（一直轮询）。
- 历史行情记录、图表、系统托盘、开机自启。
- 多级阈值（每个方向仅一个阈值）。
- 系统原生通知。
- 邮件/微信/短信等外部推送。
- GUI 配置界面、打包成 exe 分发。

## Further Notes

- 领域术语以 `CONTEXT.md` 为准：国内金价、国际金价、阈值、涨破、跌破、穿越触发、重新武装带。
- 数据源实测记录（2026-09-12）：新浪两个代码均取到数据；金投网接口返回空、不采用；上金所官网接口可用但响应体大且数值与行情站略有出入，未采用。
- 「启动即越线立即提醒」是明确决策；若日后希望相反行为（必须先回落再突破），属变更而非缺陷。
- 参考价位（2026-09-12）：国内约 940 元/克，国际约 4348 美元/盎司。
- 挂机形态为前台控制台窗口；关掉窗口即停止监视。

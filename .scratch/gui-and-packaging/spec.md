# Spec: 开箱即用与图形化设置（GUI 化改造）

Status: ready-for-agent
日期: 2026-09-14
取代: `.scratch/gold-price-alert/spec.md` 中的交付形态与配置方式两节（触发、故障、数据源语义全部沿用）

## Problem Statement

现在的监视脚本只能在这台装好专用 Conda 环境的电脑上跑：启动器写死了 `D:\App\Anaconda\...\python.exe` 的绝对路径，拷到别的电脑必然打不开；我也没法把「帮我盯着金价」这件事交给第二台机器。

设置方式也不成样子：阈值、提示音开关、弹窗时长全部埋在源码顶部的配置区里，改一个数字要用编辑器打开代码文件、找对位置、小心不碰坏别的行——这不是配置，是改程序。想要换弹窗的配色或字号，根本无处可改，写死在代码里。

交互形态也卡在「脚本」而不是「应用」：一个前台黑窗既是唯一的行情显示器又是操作对象，历史触发要么在滚动区里被刷走、要么关窗即失。

## Solution

把它变成一个**免安装的 Windows 应用**：单个 `AurumWatch.exe`，拷到任意 Windows 电脑（不需要装 Python、不需要任何环境）双击即用；首次运行自动在 exe 旁生成 `config.json`，换电脑时把 exe 和 config.json 一起拷，设置跟着走。

程序主体是一个常驻的**主窗口**行情面板：两个市场的现价、距各阈值距离、市场状态与最近的**事件记录**一目了然，底部有「设置」「立即刷新」「打开日志」三个按钮。**设置**从主窗口打开，是可视化的：阈值、提示音、外观（配色/字体/字号）、刷新等全部可改，改外观时**预览**卡片实时跟着变，还能「试弹一次」看真实效果、听真实提示音；点保存立即生效，不用重启。

提醒本身（穿越触发、弹窗、故障不误报、长时间故障警告）语义完全不变；弹窗从此与主窗口共用一套外观主题。触发与故障不再只活在滚动区里：主窗口留下近况，**日志**按天落盘可回查。另配开机自启开关与单实例保护（重复双击不会跑出两份监视）。

## User Stories

### 发布与启动

1. 作为用户，我希望它是一个免安装的单文件程序，以便我拷到别的电脑上直接双击运行。
2. 作为用户，我希望它在没有安装 Python、没有 conda 的电脑上照样跑，以便我不必在每台机器上重装一遍环境。
3. 作为用户，我希望程序在别的电脑上运行时设置从零开始也能用（内置一套合理默认值），以便我不用先做任何配置。
4. 作为用户，我希望把 exe 和配置文件一起拷走时设置跟着走，以便办公电脑和家里的电脑用同一套阈值。
5. 作为用户，我希望双击后直接看到窗口（不再有黑窗），以便它看起来是个正经应用。
6. 作为用户，我希望 exe 有名字有图标（`AurumWatch.exe`），以便在文件夹里一眼认出来。
7. 作为用户，我希望不小心把程序打开了两次时不会跑出两份监视、弹两遍提醒，以便重复双击是安全的（第二次打开会把我带到已开着的那个窗口）。
8. 作为用户，我希望设置里有一个「开机自启」开关，以便电脑重启后监视自动恢复、不用记得手动开。
9. 作为用户，我希望从源码运行时同样能跑出完整功能（供开发），以便改造期间不必每次都打包。
10. 作为用户，我希望从源码运行时「开机自启」开关置灰并说明原因，以便它不会把 Python 路径写进自启项、埋下换环境就失效的坑。

### 主窗口

11. 作为用户，我希望主窗口常驻显示国内金价与国际金价的现价和行情数据时间，以便随时确认监视活着、数据新不新。
12. 作为用户，我希望每个市场分别显示涨破、跌破两个阈值距触发的距离，以便知道离提醒还有多远。
13. 作为用户，我希望已触发待回落的方向显示重新武装线与回摆所需量，以便知道什么时候会重新具备提醒资格。
14. 作为用户，我希望每个市场有明确的市场状态（监视中 / 已触发待回落 / 数据源故障），以便不用读细节就知道它正不正常。
15. 作为用户，我希望取数失败时主窗口不用陈旧读数冒充行情，而是显示数据源故障与连续失败时长，以便我不会被静止的数字骗到。
16. 作为用户，我希望主窗口里有一个事件记录区，按时间排列最近的触发与故障警告，以便回头就能看到「刚才那声响是什么」。
17. 作为用户，我希望事件记录保留本次运行内的最近若干条，以便它不占资源又足够回看。
18. 作为用户，我希望有一个「立即刷新」按钮，以便我不想等下一个整分时马上取一次数（下一轮仍按整分对齐）。
19. 作为用户，我希望有一个「打开日志」按钮，以便直接打开日志文件夹翻档。
20. 作为用户，我希望主窗口的位置和大小被记住，以便下次打开还在我摆的地方。
21. 作为用户，我希望设置里有「主窗口置顶」开关，以便挂机看盘时行情不被别的窗口盖住。
22. 作为用户，我希望主窗口和弹窗共用同一套外观设置（背景、文字、字体、字号），以便两处观感一致、设置里也不用配两遍。
23. 作为用户，我希望关闭主窗口就是退出监视，以便术语简单、没有藏起来的托盘进程（退出时日志里留一条记录）。

### 设置

24. 作为用户，我希望从主窗口打开一个设置窗口，以便不用碰代码就能改配置。
25. 作为用户，我希望设置窗口不是模态的、能和主窗口并排，以便边看行情边调。
26. 作为用户，我希望设置里能改国内、国际两个市场的涨破、跌破四个阈值，以便行情变了随时调整。
27. 作为用户，我希望某方向的阈值留空即表示停用，以便我只关心单边行情时不受多余打扰。
28. 作为用户，我希望阈值填了非法内容时不许保存、并明确指出是哪一项错了，以便我不会在不知情的情况下带着坏配置运行。
29. 作为用户，我希望同一市场填了涨破与跌破两个阈值时，程序校验跌破必须小于涨破，以便手滑写反时当场被拦下。
30. 作为用户，我希望有提示音开关，以便在安静场合关掉声音只留弹窗。
31. 作为用户，我希望能在系统提示音与自定义 WAV 文件之间选择，以便用我喜欢的声音。
32. 作为用户，我希望有一个试听按钮，以便选音效时当场听到效果。
33. 作为用户，我希望设置里能改弹窗与主窗口的背景色、文字色、涨破色、跌破色、字体，以便按自己的喜好和屏幕环境调整。
34. 作为用户，我希望字号是一个整体缩放项（各处的字号层级自动派生），以便我只调一个数就能整体放大或缩小。
35. 作为用户，我希望设置里能改弹窗停留秒数，以便提醒符合我注意力的节奏。
36. 作为用户，我希望弹窗位置可在屏幕四角间选择（默认右下角），以便不被我屏幕上的东西挡住。
37. 作为用户，我希望设置里内嵌一个 1:1 的预览卡片，改配色、字体、字号时它实时跟着变——而且它和真实弹窗长得一模一样，以便所见即所得。
38. 作为用户，我希望有一个「试弹一次」按钮，按当前设置弹出真实弹窗并播放当前音效，以便保存前就能验证整体效果。
39. 作为用户，我希望高级项里能改刷新间隔、重新武装带比例、故障警告时长，以便按自己的行情观感调参。
40. 作为用户，我希望高级项里有一个「启动时若已越线立即提醒」开关（默认开），以便开机自启场景下我能选择要不要被立即提醒一次。
41. 作为用户，我希望设置窗口有保存、取消、恢复默认三个出口，以便调坏了能全身而退。
42. 作为用户，我希望点保存后新设置立即生效（自下一轮刷新起），不用重启程序，以便调整是即时的。
43. 作为用户，我希望取消能丢弃本次改动，以便预览看够了可以反悔。
44. 作为用户，我希望每次保存设置都在日志里留一条记录，以便回想「什么时候改过什么」。

### 配置与容错

45. 作为用户，我希望配置文件与 exe 放在一起（首次运行自动生成），以便整个程序是绿色、可携的。
46. 作为用户，我希望配置文件损坏或缺少字段时程序照常启动（按默认值运行、坏文件留备份、事件记录里有提示），以便任何配置问题都不会让我打不开程序。
47. 作为用户，我希望阈值等数值在配置里保持精确（不因浮点表示出偏差），以便 950.00 就是 950.00。

### 日志与提醒（语义沿用）

48. 作为用户，我希望日志按天分文件并自动清理 30 天前的旧文件，以便翻查方便又不用手动打扫。
49. 作为用户，我希望日志记录触发、故障警告、故障出现与恢复、程序启停、设置保存、弹窗失败这些事件，以便回查时有完整的故事线。
50. 作为用户，我希望价格越线时仍像现在一样在屏幕角落弹出小窗（不抢焦点、点击即关、到点自动消失），以便提醒不打断手头工作。
51. 作为用户，我希望价格贴着阈值抖动时不反复提醒（穿越触发与重新武装带语义不变），以便不被骚扰。
52. 作为用户，我希望断网或接口异常时没有价格提醒、且恢复后自动继续监视，以便故障不被误当成行情。
53. 作为用户，我希望连续取数失败满一段时间时有一次性故障警告弹窗、恢复后再故障会再警告，以便监视失效不会被静默吞掉。
54. 作为用户，我希望国内、国际两个市场互不牵连（一个故障不影响另一个的行情与提醒），以便单个数据源问题不拖垮整体。

## Implementation Decisions

### 模块拆分

控制台版单文件拆成包，职责如下（沿用现有「判定核心是纯函数、副作用在最外层」的分层）：

- **核心（纯函数）**：触发判定与重新武装、故障记账、主窗口所需文案的构造，以及新增的**视图模型构造**——把「一轮取数结果 + 状态 + 配置」映射成主窗口要显示的一切（每个市场的数字、文案、市场状态、事件记录条目），UI 只负责摆放，不负责计算。
- **设置（纯函数）**：设置的默认值、数据形状、规范化（缺字段补默认、坏值拒绝）、校验（正数、跌破 < 涨破）、读写与原子落盘。数值精度用 `json` 的 `parse_float=Decimal` 保持。
- **取数**：沿用现有新浪取数与解析（代码不变，仅迁移位置）。
- **弹窗绘制**：弹窗卡片的绘制函数独立成模块，**预览与真实弹窗调用同一套函数**（这是「预览所见即所得」的实现基础）。改造后主窗口即 Tk 根窗，弹窗从「自建根窗 + 队列泵」改为依附主窗口的 Toplevel；不抢焦点的 Win32 逻辑原样保留。
- **主窗口 / 设置窗口**：两个 Tk 窗口模块，只做摆放与交互，不含判定与校验逻辑。
- **编排**：轮询线程、事件流分发、单实例、开机自启、日志接线、异常兜底（无控制台后，启动期错误改用系统消息框呈现）。

### 事件流

触发与故障警告产生同一个事件流，两处消费：主窗口事件记录（内存，近 50 条）与日志（落盘）。保证「看到弹窗」与「翻到日志」讲的是同一件事。

### 配置

- 与 exe 同目录的 `config.json`；从源码运行时放在仓库根。定位规则：打包运行取 exe 所在目录，源码运行取源码目录。
- 首次运行自动生成默认配置；保存走「临时文件 + 原子替换」，避免写一半断电留下损坏文件。
- 加载时先规范化：缺失字段补默认、坏值拒绝并回退默认；整份文件解析失败则备份为 `config.json.bak` 后按默认值继续运行，事件记录与日志各留一条提示。**任何配置问题都不阻断启动**。
- 配置覆盖：四阈值（国内/国际 × 涨破/跌破，留空即停用）、提示音开关与音效、外观（背景色、文字色、涨破色、跌破色、字体、字号基准、停留秒数、弹窗位置）、刷新间隔、重新武装带比例、故障警告时长、启动即越线是否提醒、主窗口置顶、开机自启、主窗口几何。
- **配置区从源码中废除**：所有可调项只存在于配置文件与设置窗口。

### 生效方式

点保存即生效：编排层每轮刷新读取最新配置快照，阈值自下一轮起用；外观与提示音立即应用到主窗口与后续弹窗；刷新间隔的变更在下一轮重新对齐整分时生效。不可撤销操作（恢复默认）在窗口内二次确认。

### 单实例与开机自启

- 单实例：命名互斥体；第二个实例把已有主窗口带到前台后静默退出。
- 开机自启：写当前用户的 Run 注册表键，值为 exe 绝对路径；从源码运行时置灰不可用（见 User Story 10）。

### 打包与构建

- PyInstaller 单文件模式（`--onefile --noconsole`），带图标，产物 `AurumWatch.exe`；构建环境为 `aurum`（构建期需安装 PyInstaller，仅构建期依赖）。
- 构建脚本入库、可重复构建；产物目录与日志目录不入库。
- 图标以代码生成（不引入图像库依赖）。
- 界面文案全中文；代码标识符、配置键、文件名全英文。

### 删除清单

控制台的折行/原地刷新/ANSI 写屏及其测试一并删除；判定、故障、解析的测试保留并迁移到新模块路径。开发期入口脚本保留，改为从源码启动包。

## Testing Decisions

**好的测试**：只验证外部行为——喂入输入、断言输出（提醒事件序列、规范化后的配置、视图模型内容），不断言内部函数名、对象结构或 Tk 控件。

**测试缝（一条）**：仓库继续只保留**纯函数层**这一条缝，GUI、网络、打包都在缝外手动验收。缝内四组：

1. **触发判定与故障记账**（沿用既有测试，全部保留）：穿越触发、重新武装带、双市场互不串扰、故障不误报、长故障警告与恢复后再警告。
2. **配置规范化与校验**（新增）：默认值生成、缺字段补齐、坏值拒绝并回退、阈值 Decimal 精度、保存-读取往返、损坏文件回退默认、跌破 < 涨破的校验。
3. **解析器**（沿用既有测试）：两个市场字段解析、单位、时间毫秒截断、错误路径。
4. **主窗口视图模型**（新增）：给定取数结果与状态，断言主窗口要显示的每个市场的数字、文案、市场状态与事件记录条目（含数据源故障时不用陈旧读数、启动即越线的提醒开关行为）。

**先例**：现有 `tests/` 下四个 `unittest` 纯函数测试文件（判定、故障、双市场、解析与刷新对齐）即为本 spec 测试的先例；不引入新测试框架。

**手动验收（不写自动化）**：主窗口与设置窗口的观感与交互、预览与真实弹窗的一致性、试弹与试听、弹窗位置与不抢焦点、开机自启、单实例、日志落盘与清理、打包产物在**未安装 Python 的电脑**上双击运行。

## Out of Scope

- 系统托盘（最小化到托盘、托盘菜单）。
- 安装包（MSI/Inno Setup 等）——只发绿色单文件。
- 自动更新。
- 多显示器支持与自定义弹窗坐标（位置仅主屏四角）。
- 免打扰时段。
- 多级阈值（每方向仍只有一个阈值）、新增市场（白银、其它品种）。
- 历史行情记录与图表（日志明确不记逐轮行情）。
- 系统原生通知、邮件/微信等外部推送。
- macOS / Linux 移植（弹窗依赖 Win32 与 `winsound`）。

## Further Notes

- 三条已定 ADR：`docs/adr/0001-console-to-gui-single-window.md`（控制台→GUI）、`0002-single-file-exe-config-beside.md`（打包与配置位置）、`0003-event-level-logging.md`（日志策略）。
- 术语以 `CONTEXT.md` 为准：主窗口、弹窗、设置、预览、事件记录、日志、发布产物、市场状态、行情数据时间。注意「事件记录」（内存近况）与「日志」（落盘回查）是两件事，不得混用。
- 提醒语义零变更：穿越触发、重新武装带、启动即越线的默认行为、故障记账规则全部照旧——本次只改交付形态与配置方式。
- 无迁移问题：旧版没有外置配置（配置在源码里），首个正式版直接生成默认 `config.json`；当前源码配置区的默认阈值全为空，默认配置照此。
- 已知风险：PyInstaller 单文件被杀软误报（退回单目录 mode 只是构建参数变化）；Tcl/Tk 运行库须正确捆绑，因此「无 Python 机器实测」是发布前的硬门槛。
- 验收参考价位（2026-09-12 实测）：国内约 940 元/克，国际约 4348 美元/盎司。

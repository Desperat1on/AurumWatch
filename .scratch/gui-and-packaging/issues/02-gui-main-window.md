# 02: 主窗口上线——行情面板取代控制台

**What to build:** 启动后出现常驻 GUI 主窗口（不再有控制台黑窗）：每个市场显示现价、行情数据时间、各启用阈值距触发的距离（已触发待回落的方向显示重新武装线与回摆所需量）、市场状态；底部有[立即刷新]按钮；取数失败时显示数据源故障与连续失败时长，不用陈旧读数冒充行情。越线弹窗照旧，但弹窗改为依附主窗口，不抢焦点、点击关闭、到点自动消失的行为不变。主窗口要显示的内容由一个纯函数（视图模型）算出，UI 只负责摆放。

## Comments

实现记录（2026-09-14）：

- **模块**：新增 `viewmodel`（纯函数：一轮取数结果 + 状态 + 记账 → 窗口要显示的一切）、`main_window`（Tk 主窗口，只摆放）、`schedule`；重写 `app`（编排：主窗口 + 轮询线程 + 队列）；`popup` 由「自建根窗 + 后台线程泵」改为挂靠主窗口的 Toplevel（`attach(root)`，泵在主线程的 `after` 里取队列）。删除 `console.py`。依赖仍单向：`app → main_window／popup／viewmodel／quotes／alerts／failures／settings`。
- **视图模型**：`WindowView`（抬头、本次刷新、下次刷新、各市场面板）＋ `MarketView`（名称、说明、正文行、市场状态）；正文行是 `Line(text, tone)`，tone 只说「价／涨／跌／暗／警告」，窗口按 tone 取颜色——UI 不判断行情、不算数，也不拼文案。
- **`schedule` 新模块**：`next_refresh_delay` 原在 `quotes`（唯一出网模块），视图模型要算「下次刷新」，直接引会把纯函数层拖进 `requests` 依赖，故单独立一个不依赖网络的纯函数模块（ticket 01 评审也提过这一条）。
- **线程分工**：Tk 只在主线程碰；取数（阻塞网络）在后台线程，每轮算好的 `WindowView` 经队列交给主线程（`after` 200ms 一次）上屏——窗口不因取数卡住，提醒也不会漏。
- **`[立即刷新]`**：按钮 → `threading.Event.set()`；轮询线程把它当作等待的提前结束信号。实测（改完下面那条对齐口径后复验）11:35:29 按下 → 立即出一轮，且「下次刷新」仍是 11:36:00（约 31 秒后），11:36:00 那一轮照常取数（按钮用真实 `tk.Button.invoke()` 触发，不是直接调回调）。
- **对齐口径的一处主动改动**：旧版用「本轮开始的时刻」算下次刷新，取数慢时会冲过整分、下一轮落到分中。现在每一轮的时刻取在取数之后，「本次刷新」「下次刷新（约 N 秒后）」与真正要等的秒数三者同源——每一轮都落在整分上，窗口上的秒数与实际等待一致（评审指出的「两个时钟」即此）。副作用是「本次刷新」显示的是取数完成的时刻（如 11:36:01，下一轮仍 11:37:00），读起来比原来的整分时刻更贴实际。
- **配色暂有两份**：主窗口的涨/跌/警告色与字体目前与 `popup.py` 各写一份（`main_window.TONE_COLOR`／`popup.DIRECTION_COLOR`），靠注释对齐。ADR-0001 要的「主窗口与弹窗共用一套外观」由 ticket 04 落地外观设置时收成一处。
- **无控制台**：`启动金价监视.bat` 改为 `cd /d "%~dp0"` ＋ `start "" ...pythonw.exe -m aurumwatch`——cmd 立即返回、不留黑窗（实测 .bat 61ms 退出、进程为 pythonw）。`.bat` 的注释用英文：cmd 按字节读 UTF-8 多字节会有偏移，中文注释实测被读成命令并报「不是内部或外部命令」。启动期与运行期异常改用系统消息框（`MessageBoxW`），Tk 回调里的异常走同一条兜底——没有控制台可打印。
- **弹窗**：不抢焦点、点击关闭、到点自动消失的逻辑逐字保留，只把根窗换成主窗口、泵挪到主线程。实测：三个弹窗都在工作区右下角（右、下各留 24px）、上下叠放、`topmost=1`、`overrideredirect=True`；弹窗出现前后的前台窗口都不是弹窗；Tk 事件模拟点击后该弹窗销毁、剩余数减一；停留时长到点后剩余数归零；`drain_ui_errors` 全程为空。
- **长报错折行**：取数失败的报错单行很长，不折行时 Tk 会把窗口撑到 3325px 宽（实测）。卡片正文与提示行加 `wraplength=520`，窗口回到 629px 宽；ticket 04 做字号缩放时应让折行宽度随基准字号换算。**未手验**：手动拖动窗口改变大小后的观感。
- **故障验收**：把数据源指到本地空端口（必然连不上）后，两个市场各自显示「!! 数据源故障：<原因>」「已连续失败 N 秒（满 X 分钟将弹出警告／已弹出警告）」「状态：数据源故障」，全程不出现现价、行情数据时间与阈值行；连续失败满阈值的下一轮弹出两张琥珀色故障警告弹窗（枚举到两个可见 Toplevel，位置同右下角）。
- **测试**：新增 `tests/test_viewmodel.py` 18 个用例（整帧逐行比对、故障轮不出陈旧读数、涨/跌两条方向的重新武装与回摆文案、下次刷新整分对齐）；原控制台渲染的断言（test_alerts 的 ConsoleRendering 4 个、test_failures 的 FailureConsole 4 个、test_markets 的 ConsoleShowsEachMarket 4 个）在视图模型上重写，`NextRefreshDelay` 3 个随函数挪进 `test_quotes` 的既有类，`test_console.py` 10 个随折行写屏整体删除，`WarningLogLine` 1 个删除（落盘日志的文案由 ticket 05 起草）。全套 80 个用例绿（85 − 23 + 18）。
- **未手验**：打包产物（ticket 07）、源码运行的「开机自启」置灰（ticket 06）、多显示器下弹窗位置（spec 已把多显示器列为 Out of Scope）。弹窗的「点击关闭」用 Tk 事件模拟而非真鼠标点击，但几何、叠放、topmost、前台归属都实测过。

## Comments

实现记录（2026-09-14）：

- **模块**：新增 `single_instance`（命名互斥体 + 把已有主窗口带到前台）与 `autostart`（当前用户 Run 键的读写）；`app.main()` 开头过一道单实例，第二个实例连日志都不开就退场；`settings_window` 的高级组多一个[开机自启]勾选框（源码运行置灰 + 说明），[保存]时先落注册表再写配置。测试新增 `tests/test_autostart.py` 15 个用例（写入的值可当命令行跑、取消删干净、源码运行一个字不写、写不进去要能说得出原因），全套 218 个。
- **认主窗口不能只按标题**：Tk 的 Toplevel 默认继承应用标题，弹窗与主窗口同名，而弹窗是置顶的——`FindWindowW(None, "AurumWatch")` 实测取回来的是那个贴在屏幕角上、半秒后自己会消失的小窗（探针里根窗口 0x11a168c、弹窗 0x761676，取到的是后者）。改成枚举全部同名窗口、按**有没有标题栏**（`WS_CAPTION`）认主窗口：弹窗用 `overrideredirect`，没有这一位。实测主窗口 + 无边框弹窗 + 真实弹窗 + 设置窗同时在时，认出的仍是主窗口。
- **前台不是想拿就能拿**：Windows 只把前台让给前台进程或由它拉起的进程。双击 exe 的正是资源管理器（前台进程），这条正路走得通；从终端再起一次这种情形要被挡下（自动验收里 `SetForegroundWindow` 返回 0 就是被挡了——验证进程不是前台进程）。所以补一条退路：要不到前台就 `FlashWindowEx`（`FLASHW_ALL | FLASHW_TIMERNOFG`，一直闪到用户点开），总比什么都不发生强。
- **注册表是[开机自启]的唯一真相，config.json 里不存它**（spec 的「配置覆盖」一节列了开机自启，这里按「怎么才对」办）：配置文件是要跟着 exe 换电脑的，可那台机器的启动项里并没有我们——存两份，界面显示的和实际会不会自启就会分叉。判断只看**值名在不在**：同一个名字下只能有一条启动命令，谁写的都是写给 AurumWatch 的；勾选时总是重写成本次运行的 exe，所以搬了家、重新打包之后保存一次即可修正路径（这也是不比较路径的原因）。[恢复默认] 对这一项等于「回打开窗口时的实际状态」，不写盘。
- **值写成带引号的绝对路径**（票面写「值为 exe 绝对路径」）：路径里有空格而不加引号时，Windows 会把它按空格切开——`C:\Program Files\…` 会被当成 `C:\Program.exe`，自启静默失败还可能被同名程序顶替。实测用 Windows 自己的命令行解析器 `CommandLineToArgvW`：加引号解析出 1 个整路径，不加引号解析成两截。
- **写不进去就整笔不保存**：[保存] 先落注册表再写配置，注册表那一步失败（权限等）就留着窗口把原因说清楚——配置写进去、注册表没写成的话，用户得猜是哪一半生效了。
- **源码运行不碰注册表**：`autostart.exe_path()` 只在打包形态（`sys.frozen`，与 `config.base_dir()` 同一个标记）返回 exe；源码运行返回 None，设置窗口据此置灰，`set_enabled(True)` 也会抛 `ValueError`——两道闸，界面之外也写不进去 python.exe。
- **顺带放宽了组下说明的折行宽度**：`_hint` 原本与红字共用 240px（红字挤在输入框右边那一列，说明独占一行），新的自启说明折成四行、行尾只挂一个「用」字；另立 `HINT_WRAP_AT_BASE = 320`。
- **手验**（脚本与截图在临时目录、不入库）：
  - **单实例**（真入口 `app.main()` + 驱动子类起窗后弹一个真弹窗）：重复启动退出码 0、耗时 0.3s、日志一行不加、不产生第二个窗口；弹窗在场时认出的仍是主窗口；最小化的主窗口被 `SW_RESTORE` 还原；要不到前台时任务栏闪烁（用「再叫一次 `FlashWindowEx`，返回值表示此前在不在闪」实测为真）。**几乎同时启动两份**（间隔 0 / 0.05 / 0.2 秒）三种情形都恰好一份在跑。
  - **开机自启**（真注册表，验完清理）：源码运行勾选框 `state=disabled`、置灰色为 faint、说明写的是「从源码运行时不可用（不把 Python 路径写进启动项）；打包后可用」，硬点[保存]也不动注册表；假装打包运行后勾选[保存] → 注册表写入 `"D:\Apps\AurumWatch\AurumWatch.exe"`，重开窗口显示已勾选，取消[保存] → 值消失（收尾复查 Run 键下只剩 OneDrive／Ditto／Mem Reduct 等原有项，无 AurumWatch）。
  - **「重启后自启生效」用替身验**（发布产物还没打包，见 ticket 07）：把一个带空格路径的 .bat 当 exe 写进 Run 键，`CommandLineToArgvW` 解析出整路径 → 照它跑起来 → 日志出现「AurumWatch 启动」、窗口真的起来了、按关闭主窗口退出后进程结束。
  - **设置窗口截图**（源码／打包两种形态）：窗口自然尺寸 1520x805 未变，勾选框 110x38、说明两行排得下。
- **未手验的一处**：「真实双击把已有主窗口带到前台」这一条，自动验收里 `SetForegroundWindow` 被前台权限挡下（验证进程不是前台进程），只能验到「还原 + 要前台/闪任务栏」这一步。请真人双击一次确认（资源管理器当前台进程时走得通）。另：两份 exe 分别放在两个目录时共用一个名额，先跑的那份占着——名字不带路径，与本票「一个会话只跑一份监视」的口径一致。
